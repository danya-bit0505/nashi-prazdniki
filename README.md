# Наши праздники

PWA-календарь семейных праздников: дни рождения, годовщины свадьбы, именины, дни памяти. Листаешь по месяцам — сразу видно, у кого праздник. Напоминания уведомлениями.

Vanilla JS, без сборки, GitHub Pages. Работает офлайн (cache-first SW), данные в `localStorage` + копия в Cache Storage для service worker.

## Что умеет

- Сетка месяца с иконками праздников, стрелки ‹ ›, свайп, тап по названию месяца — назад к сегодня.
- Под сеткой — список праздников месяца: возраст / сколько лет свадьбе (с названием: «50 лет, золотая свадьба»), «через N дней».
- Блок «Скоро» — ближайшие 8 дней.
- Тап по дню — подсветка его праздников; кнопка внизу превращается в «＋ Добавить на 15 октября».
- 29 февраля в невисокосный год празднуется 28-го.
- Размер текста — 4 ступени в настройках (зум страницы отключён).
- Резервная копия в JSON-файл и загрузка обратно (слияние по `id`).

## Деплой

1. Залить содержимое папки (кроме `server/`) в репозиторий, включить Pages (branch `main`, root).
2. Открыть на бабушкином телефоне в Chrome → «Установить приложение» / «Добавить на главный экран».
3. ⚙️ → «Включить уведомления».

При изменениях — поднимать `CACHE_NAME` в `sw.js` и `APP_VERSION` в `js/app.js`.

## Как работают напоминания

| Уровень | Когда срабатывает | Что нужно |
|---|---|---|
| При открытии | каждый раз, когда приложение открыто/развёрнуто (8:00–22:00) | только разрешение |
| Periodic Background Sync | Chrome/Android, установленное PWA, примерно раз в 12+ ч — когда браузер решит | установить PWA |
| Push через GitHub Actions | каждый день ~09:17 МСК, даже если приложение не открывали | настройка ниже |

Повторы отсекаются: у каждого напоминания ключ `id|дата|за сколько дней`, он же `tag` уведомления, а показанные помечаются в Cache Storage — push и локальная проверка не задублируют.

Надёжно «каждое утро» — только push. Остальное — подстраховка.

**iPhone:** уведомления только у приложения, добавленного на экран «Домой» (iOS 16.4+). Periodic sync там нет — только push или при открытии.

## Настройка push (один раз)

1. Создать **приватный** репозиторий, например `prazdniki-data`. Положить в его корень содержимое `server/` (`remind.mjs` и `.github/workflows/remind.yml`).
2. Сгенерировать ключи: `npx web-push generate-vapid-keys`.
3. В приватном репо → Settings → Secrets and variables → Actions:
   - Secrets: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:твоя@почта`)
   - Variables: `APP_URL` = `https://danya-bit0505.github.io/<репо-приложения>/` (скрипт берёт оттуда `js/core.js` — одна логика дат на страницу, SW и сервер)
4. Fine-grained токен: доступ **только** к `prazdniki-data`, Contents: Read and write.
5. В приложении: ⚙️ → «Синхронизация и push» → репо, токен, VAPID public key → «Сохранить» → «Подписаться на push».
   Приложение само кладёт в репо `events.json` и `subscriptions.json` (подписок может быть несколько — например, твой телефон тоже).
6. Проверить: Actions → «Напоминания о праздниках» → Run workflow.

Workflow сам удаляет протухшие подписки (404/410) и раз в месяц коммитит `last-run.txt`, чтобы GitHub не отключил расписание через 60 дней без активности.

Данные — в отдельном приватном репо, потому что репо с Pages публичный, а там имена и даты родственников.

## Формат данных

```json
{ "id": "lx3k9a2b", "name": "Маша, внучка", "type": "birthday",
  "day": 22, "month": 10, "year": 2015, "remind": [0, 1],
  "note": "Любит лошадей", "updatedAt": 1761050000000 }
```

`type`: `birthday | wedding | nameday | memorial | other`. `remind` — за сколько дней (0 = в сам день). Удаление — tombstone `{id, deleted: true, updatedAt}`, слияние по последнему `updatedAt`, tombstone старше 400 дней выкидываются.
